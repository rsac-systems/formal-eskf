# INS Diagnostic Reporting Tests

**Status:** Draft

**Scope:** [R-INS-DIAGNOSTICS](../../../requirements/runtime/diagnostics.md).

**Level / purpose:** Component composition, unit checks of retained numerical
results and regression through the production staged INS session. The
[allocation](../../diagnostic-reporting-tests.md) owns the complete runtime/PX4
acceptance boundary; this family binds its portable cases to the case runner.

**Profiles:** Binary64, synthetic 250 Hz, Eigen and PX4 matrix; default generated
exact operations and dense/approximate dependencies. Height rollback also uses
its existing binary32/binary64 owner family. No strict-profile implementation,
physical accuracy, embedded WCET or formal proof is implied.

**Setup and oracle:** Actual owners with deterministic receiver/filter clocks.
Controlled priors, counters and failed dependencies use the existing test friend.
Independent S = 4 fixtures distinguish accepted/rejected/failed gate results;
retained fields use exact comparisons. Source/phase fixtures exercise actual
admission, delayed fusion, reset/rebase and publication-independent reads. The
three-run comparison checks numerical noninterference under different reader
cadences, not estimator accuracy against ground truth.

## Dependency and coverage boundaries

The case IDs retain the original allocation. Numerical gate-domain, late-failure
and coefficient coverage belongs to [measurement fusion](gnss-navigation.md).
The snapshot cases check that those results remain reportable; they do not rerun
all numerical partitions for every sensor. The
[height owner](height-aiding.md) additionally checks that a successful first
candidate followed by a failed second source rolls back estimation and reporting
events while preserving tentative gate evidence. Such evidence is not a commit.

[Observation history](storage-alignment.md), [IMU history](storage-alignment.md),
[GNSS lifecycle](gnss-navigation.md) and the source-specific families retain their
integer-boundary, retirement/overflow and recovery assertions. The reporting
family checks the session's corresponding counters and retained/current views.
The PX4 cases, actual consumer checks, observed transport loss, concurrent
exchange and deployment budgets remain in the parent allocation. Native results
do not close external-logger or undeclared embedded-target qualification.
